# ADR0041 — Explicit checkpointed WAL state behind the private reader

Date2026-10-30. Status: offline software implemented and independently reviewed R2; release/actual host admission remain separate.
Issue [257](https://github.com/ZP151/quantmesh/issues/257). Actual human approved offline implementation/verification of design e46450c6 through receipt1462eae7; execution281575d1. The copied design pending header is historical, superseded by this receipt. No repeated approval.

Frozen v1 requires a real WAL. Genuine checkpoint/normal close can remove it; pretending absence is an empty present file changes the evidence contract. Retain v1 and introduce explicit v2 PRESENT/ABSENT, never optional/autodetected state. v2 uses its new actual approval/design/authority. Original cut/111keys/full17/NULL/rawJSON/SQL/_tail_rows/math, OSRO, 256MiB aux/shared2GiB and normal128MiB/temp0/public API remain unchanged.

PRESENT retains real-file identity/content/OSRO checks. ABSENT binds a held RO parent directory and exact ENOENT plus completed checkpoint and already activated absence/epoch receipts. The hash DAG is checkpoint -> epoch -> absence -> admission; no future posthash/normal-close hash appears in initial admission. All source/time/runtime/DB/generation/nonce/namespace/no-writer/parent contexts must agree. Pending recovery is incompatible with ABSENT. Old readers reject v2; new readers preserve strict v1 and refuse unused extra proof FDs.

All admission models/guards/OS adapters stay inside history_ram_aux.py, whose actual profile_source_sha256 already pins the entire guard. history_wal_state.py exports the pure offline producer serialization and schemas; runtime admission never imports it as an unpinned verifier. This costs a larger private module rather than silently widening an already frozen runtime schema or changing hash semantics.

The trusted controller supplies root0444/single-link bounded readonly checkpoint/absence/epoch FDs with independent admission SHA. Source owns only noninheritable duplicates plus its readonly parent FD, validates exact bytes/lineage and live actor/guard/resource/source/namespace facts. It cannot prove checkpoint success or continuous host exclusion merely from nonzero receipt hashes or two ENOENT samples. Controller must already have real completed checkpoint provenance and enforced no-writer/namespace coverage; an observer gap or lost exclusion unlinks the original epoch token permanently. Recreating a name cannot repair the original held inode. Source permanently revokes and closes its ABSENT reader/evidence on any failed check; normal explicit close still works after loss. Caller descriptors are not advanced/closed.

Source boundary checks do not replace the trusted controller's continuous enforcement. Final external report release still requires full posthash/independent original111x17/math and Product/oracle/guard/independent normal-close evidence for the exact admission/branch/epoch. The producer adapter serializes and validates supplied records; it obtains no host facts and issues no operational authority. Local tiny genuine-checkpoint DB + real readonly API uses explicitly synthetic privileged OS/FD vectors; Windows projects POSIX nlink0 for epoch tests. It is software evidence, never actual native or financial acceptance.

A one-line private opener owner binding is necessary for ABSENT to close the reader before a revoked-epoch exception returns; existing v1/PRESENT close behavior and all original SQL methods remain protected. No source writable connect, fake WAL, new data, model/provider, dependency, environment or frontend change is introduced.

D(source shutdown/checkpoint/recovery growth), full E(other execution high-water), continuous actual exclusion and bounded independent operational restore remain unknown. The software approval grants no stop/freeze/reconfigure, permission, host/SSH, original-data API/reference or maintenance authority. Release remains exact-head Publisher CI/review/normal merge/catalog; real acceptance remains UNMET.
