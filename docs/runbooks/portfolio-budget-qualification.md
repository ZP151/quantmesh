## Fixed-command descendant cleanup

Standards R1 found that the earlier direct-PID cleanup could leave a stopped
`postgres --boot` descendant of initdb alive. The actual regression records
the surviving boot backend before test-only retirement of that newly created
leaked fixture. The first fix passes the same regression and the broader
native verifier; final R2 acceptance remains recorded in the handoff.

Each fixed command now starts a new session/group. Only that kernel SID/PGID
is inspected. Every live member needs the current UID, start ticks, admitted
executable/hash and inherited command owner nonce; the direct command also
needs its exact argv. The upstream initdb shell may exec the pinned PostgreSQL
binary within the same pidfd generation. Such admitted image transitions are
recorded, never used to adopt an unrelated PID. The base-system `/bin/sh`
image is measured at launch and appears in family receipts when observed.

Cleanup freezes positively identified members through pidfds, rescans for a
stable stopped family, then signals only registered pidfds. It never sends a
blind PID/PGID kill. Unknown membership refuses cleanup and restores only
eligible members paused by the qualifier. A physical test with a deliberately
unmarked live member proves refusal and survival; its separate test-only
custodian retires that newly created fixture afterward. Unrelated siblings
remain outside the command's isolated session.

A temporary current-process Linux subreaper adopts orphaned descendants.
Only known member PIDs are reaped; terminal pidfds, observed images, signals
and reaping outcomes appear in command and witness family receipts. Its
previous setting is restored after the last cleanly closed family. Command
cleanup has a bounded three-second freeze/terminal deadline; unknown identities
remain pending and cannot qualify. Frozen historical helpers are unchanged.

The old handoff journal entry was hashed before a later journal write. The
exact original bytes are recovered and archived under their original SHA256;
the root's original mismatch observation remains preserved. Final handoffs
are generated only after the journal is finalized, and every listed evidence
hash is checked afterward. No original database/observer/runtime proof is
