## Outcome

Turn the fixture-verified RC1 engineering shell into a product the operator can
actually evaluate. A fresh local start must offer a coherent, populated and
safe paper-trading workflow, with optional provider/import paths, visible data
provenance, useful failure states and a production-quality operator interface.
Publish RC2 only after automated verification and a human browser acceptance
pass. Do not promote `v0.1.0` from RC1.

## Why this iteration exists

Operator review of RC1 found that every route looked like minimally styled
server-rendered HTML. The main navigation exposed raw API links, pages started
empty, and neither deterministic sample data nor a connected provider made the
business workflows testable. The CSS was loading and the backend contracts were
present; the failure was runtime assembly and product experience, not a broken
stylesheet. RC1 therefore remains an immutable engineering baseline, not an
operator-accepted release.

## Product and design direction

**Design read:** a redesign of a local quantitative operator workstation for a
solo researcher/trader, with a restrained dark-technical language, leaning on
an owned shadcn/ui system plus specialized data-grid and financial-chart
libraries.

- Visitor mode: **Operate**. Scanability, state clarity and familiar terminal
  behavior outrank decorative expression.
- Visual direction: near-black neutral surfaces, one controlled green accent,
  compact typography, strong numeric alignment and restrained state motion.
- Design dials: `DESIGN_VARIANCE=4`, `MOTION_INTENSITY=2`,
  `VISUAL_DENSITY=8`.
- The taste-skill is an anti-template and quality guard for the shell and any
  future public surface. Its own scope excludes dense dashboards and data
  tables, so it must not be treated as the workstation's component system.
- Impeccable owns product-UI shaping, loading/empty/error states, hierarchy,
  accessibility and final visual review. `PRODUCT.md` is its durable product
  context.
- Explicit anti-references: the RC1 raw HTML shell, default unmodified shadcn
  examples, generic SaaS card grids, decorative neon/glass, fabricated charts,
  and blank pages that provide no recovery action.

## Reuse-first frontend architecture

Write ADR-0013 before implementation and validate these choices in one thin
vertical slice:

1. Keep FastAPI and the existing Python domain/research/execution layers.
2. Add a React + TypeScript + Vite application under `frontend/`.
3. Initialize shadcn/ui and copy only selected components through its CLI. Own
   and theme that source; do not copy the entire upstream repository and do not
   ship the default visual treatment.
4. Use Tailwind CSS for tokens/layout, TanStack Query for server state and a
   generated OpenAPI TypeScript client to keep frontend/backend contracts in
   sync.
5. Evaluate TanStack Table for dense grids, TradingView Lightweight Charts for
   market series, and Apache ECharts for portfolio, calibration and scenario
   views. Adopt only the smallest licensed set that passes the spike.
6. In development, Vite proxies `/api` to FastAPI. For local production, the
   compiled assets are packaged and served by FastAPI so the operator still
   starts one process and does not need Node.js at runtime.
7. Keep legacy URLs as redirects or compatibility routes while replacing the
   primary information architecture.

## Information architecture target

Replace the two rows of flat links with one persistent application shell:

- **Overview:** portfolio equity, cash, exposure, fresh market state, current
  alerts and actionable first-run status.
- **Markets:** instruments, watchlist, quotes/order books, cross-venue context
  and forecast evidence.
- **Research:** experiments, model comparisons, promotions and AI research with
  citations.
- **Paper trading:** order ticket, orders/fills, positions and P&L as one
  continuous flow.
- **Risk & operations:** limits, alerts, audit, connector health, data imports,
  enablement and the global kill switch.

Raw API routes belong in developer diagnostics, not primary navigation.

## Operator acceptance gates

RC2 is acceptable only when all statements below are true:

1. A fresh user can start a populated demo without credentials or manual data
   injection and sees useful state within 60 seconds.
2. The complete research-to-paper-trade flow works through the UI without CLI,
   database access or direct API navigation.
3. Every market value and forecast displays provenance, timestamp and freshness;
   synthetic data is unmistakably labeled.
4. A paper order visibly changes orders, fills, positions, cash, P&L, risk and
   audit history, and the change survives restart.
5. At least one public-data connector and one file-import path can be exercised;
   their unavailable and malformed states are understandable and recoverable.
6. The interface is visibly a coherent QuantMesh product, not stock shadcn and
   not raw HTML, at supported widths and with keyboard navigation.
7. Live execution remains unavailable without the existing explicit enablement
   gates; AI cannot directly submit or approve an order.
8. Clean-checkout release, backend, frontend and E2E checks are green and the
   isolated acceptance install matches the tagged commit.
