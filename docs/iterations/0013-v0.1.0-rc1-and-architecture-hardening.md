## Review findings

### Release truth and process

1. `CONTEXT.md`, the roadmap, the iteration index and iterations 0006-0012
   retained pre-merge status even though M4-M10 were complete. This iteration's
   first checkpoint reconciles those durable records.
2. `docs/goals/ACTIVE.md` accumulated detailed milestone history and stale
   branch/PR state. It must remain a concise current frontier; Git history and
   completed iteration records retain the detailed evidence.
3. The package version is `0.1.0`, while the old release process coupled every
   roadmap milestone to a `0.M.n` version. Product release identity is now
   decoupled from internal milestone numbers: package version `0.1.0rc1`, tag
   `v0.1.0-rc1`, then package/tag `0.1.0`/`v0.1.0` after acceptance.
4. The clean-checkout golden path leaves an untracked `golden-root/` artifact.
   Release verification must write generated state under an explicit temporary
   root or remove it on successful completion.

### Security workflow

The Security workflow is correctly path-filtered, but `pyproject.toml` does not
currently trigger it. A dependency declaration can therefore change without
running the audit job. Add `pyproject.toml` and the Security workflow file to
the trigger surface and add a deterministic consistency test between declared
dependencies and `requirements-audit.txt` where practical. Resolve the ambient
license-inventory drift above and prove the result in a newly created release
environment.

### Architecture deepening candidates

These are sequenced after the RC is publishable. Do not design or migrate all
of them in the release PR.

1. **Strong — durable JSONL persistence module (top recommendation).** Atomic
   replacement, fail-closed parsing, duplicate handling, hostile-path checks
   and schema validation repeat across execution journals, research
   registries, operations ledgers, AI decision logs, event mappings and
   watchlists. Deepen one module so callers cross a small interface and domain
   registries retain only record policy. This increases leverage and locality;
   crash/corruption tests concentrate at one seam.
2. **Strong — cross-venue reconciliation module.** The shared vocabulary is
   shallow while Moomoo and Hyperliquid implementations repeat pairing,
   classification, tolerance and adoption flow. Deepen the shared module and
   keep venue-specific evidence/status mapping in adapters. Preserve ADR-0006
   conservative defaults.
3. **Strong — execution numeric policy.** Price, quantity, fee and tolerance
   behavior uses distributed float operations and local rounding. First write
   characterization tests and an ADR covering tick size, lot size,
   quantization and comparison; make no representation change in the RC.
4. **Worth exploring — local runtime assembly.** Workstation construction,
   local paths, stores and recovery are concentrated in a large implementation.
   Explore a deeper runtime module after the first three candidates; it is not
   release-critical.

## Delivery protocol for a solo developer

- Prioritize Phases A-D. Architecture work may not delay the first RC.
- Use one coherent PR for release documentation, metadata, CI and verification
  automation. Avoid one issue or PR per checkbox.
- After the RC, use one short-lived PR per risky architecture slice. Small
  documentation corrections may ride with the owning slice.
- The primary agent acts as Tech Lead: language, database, financial numeric
  representation or major seam changes require an ADR before implementation.
- At every checkpoint update this file and keep `docs/goals/ACTIVE.md` concise.
- Branch from `origin/main`; after squash merge reconcile local `main` by
  fast-forward only. Never push directly to protected `main`.

## Safety gates

Moomoo OpenD simulated-account and Hyperliquid testnet drills are optional
post-merge validation gates requiring an explicit operator environment. They
do not block the fixture-verified RC. Real-money trading, mainnet wallet
signing, live broker orders, credentials, paid infrastructure and AI order
authority remain forbidden without explicit human approval and a recorded
enablement transition carrying the exact gate text.
