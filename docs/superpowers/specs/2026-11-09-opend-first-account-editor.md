# Current-instance first ACCOUNT editor acknowledgement

Issue: [301](https://github.com/ZP151/quantmesh/issues/301). Preparation only;
Planner authorized source/TDD/review/publication preparation, not actual input.

The current6b4 service has the correct direct inherited private TTY: UID997,
0600, foreground guard/vendor group/session, same stdio object and echo off.
One complete57-task observation found EPOLL4/FUTEX47/OTHER6 and no read/readv.
That is not proof an epoll watches the TTY or an input handler is ready. The
default exactly-one vendor read(fd0) predicate remains unchanged and false.

**Selected approach.** Add an explicitly versioned first-account route only for
nonce6b4ad17d130c45e583005670612eca52, origin6d58ecc4, manifest5693b886 and
current control67f98441. Rejected alternatives: interpreting EPOLL as read-ready
has no evidence; a generic attach console exceeds this slice. This route proves
destination before paste, then application editor acknowledgement before Enter;
it does not claim equivalence to the original blocked-reader assurance.

1. The unchanged bound-class source/cohort/pidfd/socket/native/terminal guards
   remain. Additionally hold guard/vendor stdio descriptors; require identical
   character TTY997:0600, stable starts/groups/sessions/foreground and echo/echonl
   off before and after each observation/effect. Require exactly the two-row
   public ACCOUNT prompt plus empty pinned marker, never an existing edit,
   PASSWORD, uncertain observation, changed identity or an old journal.
2. The original create-only CB1-EFFECTS Journal owns STARTED_ACCOUNT and its
   account PASTE intent/submission. A paste-only role accepts one ACCOUNT value,
   rejects all generic submit/Enter/password operations, and permits one
   own-buffer paste with no Enter. The Windows client obtains only the exact
   target/Type1/SID UserName through bounded CredEnumerate; it never calls
   CredRead or dereferences/copies/serializes CredentialBlob. Windows may return
   blob bytes within its API allocation; no OS non-mapping/zeroization claim is
   made. Free the original allocation and wipe owned mutable username buffers.
3. After the paste, require fresh held identity/TTY proof and original helper
   edited_matches(ACCOUNT, same username) on native two-row rendered output.
   The original pre-paste editor was empty; a matching changed render with
   terminal echo still off is the acknowledgement. Raw text/value/hash stay
   inside the trusted process. No ACK, partial write, timeout or changed object
   is finite INPUT_STUCK_NO_RETRY: no clear-input, compensating Enter, re-paste,
   material, restart or retry. Only owned tmux buffer cleanup is allowed.
4. A separate first-account Enter role requires that actual ACK, same object,
   same journal at ACCOUNT_PASTE_SUBMITTED and fresh exact edited ACK before
   and after the durable Enter intent. It permits only one fixed Enter. It then
   revokes first-account policy and hands the same pane/journal to original
   serve. PASSWORD/REMEMBER retain original prompt, readiness, journal, source,
   input verification and cleanup. Client reads original password material only
   after ACCOUNT_ENTER_SUBMITTED and PASSWORD, under its own durable one-use
   intent; its returned account must equal the retained username. No remember,
   legal agreement, SDK, service or trading policy changes.

**Risks and limits.** Pre-paste destination proof does not establish consumption;
the username may remain queued if the vendor is unresponsive. ACK is editor
protocol evidence, not authentication, SDK READY or financial qualification.
Trusted same-UID/root external actors remain within the already accepted
boundary; snapshots cannot eliminate concurrent changes between observations.
No values, their hashes or private lengths enter records/logs/argv/env. Existing
UNKNOWN, spent SDK check01 and old holds remain unchanged.

**Acceptance.** Targeted tests must exercise original parser/edited_matches and
Journal, empty/nonempty/private/password prompts, same-journal order, lost TTY/
source/socket/owner, failed persistence/effects, mismatched/absent ACK, duplicate
paste/Enter, delayed password material and bounded username API/free/wipe.
Freeze exact full candidate, original dependency pins, deltas, geometry and
independent narrow review. Parent adjudicates actual input once after this
concrete candidate; no new ordinary permission question to the user.
