# Invocation-bound OpenD exit witness

Refs #263. Diagnostic-only software: retain the last completed pane/owned-child stage and reaped outcome, without observing private terminal/vendor data or fixing an unproved cause. Current fourth-start records prove Source/Pre/Post success and a later dead unit; the two current complete ATTEMPTED marker views match its control. Neither marker nor ACK proves release/exec. No fifth start/window/SDK is authorized.

## Selected design and alternatives

Inline the witness in the already pinned stage_console.py; guard, recovery, base/drop-in, observer and resource/identity/mount algorithms remain unchanged. No new dynamically imported module, dependency, actor, writable destination or diagnostic environment. Stdout/journal capture violates privacy/retention; ptrace/additional observer expands authority/timing, so reuse the existing owned runtime directory, report pipe, pidfds, registration, reap and cleanup. c8/schema4 ONLY; other modes retain their existing behavior. Existing c8 RuntimeDirectoryPreserve=yes permits retained runtime records; do not change STATE or the unit.

## Header, identity and early refusal

_prepare creates ONE fixed runtime/invocation-witness entry after ordinary admission and manager validation, O_EXCL/no-follow/CLOEXEC/0600/997:987/single-link. Reserve32768 real bytes with posix_fallocate and verify size/allocated blocks; fsync before any fork/consume. Collision, unsupported reservation or uncertainty denies; no overwrite/delete/fallback. Header binds manager InvocationID, nonce, protected actual launcher SHA and current public control SHA. PID/start fields in the shared header are neutral0; PREPARED/PANE_ENTER events carry actual process/start and retained parent/start. This avoids falsely treating prepare PID as pane PID.

Before pane select_console_window/first _admit: diagnostic-only fixed systemctl show Id/InvocationID/ControlGroup/MainPID, current process start/cgroup and live retained parent metadata must agree with protected source/control and the held header. The existing ordinary _admit and manager/terminal gates still follow unmodified. Missing/unbindable header yields UNKNOWN/no attribution and prevents release, never grants authority. Hold a directory FD and verify named/held inode/type/uid/gid/mode/nlink/size around writes; do not follow replacement paths.

## Bounded events and child protocol

64 write-once512-byte slots; header included. Hard cap48 attempted writes/24576 attempted bytes, fixed total file32768. Each slot has fixed binding digest, sequence, closed event JSON/zero padding and checksum. Short write is failure, never retry or overwrite. Events are fixed enums: prepare/pane/admission/context, registered child, final admission, consume entry/return, gate-write entry/actual return, actual ACK, explicit child report, observed owned vendor executable, reaped status, cleanup signal requested/actual result, backend finish, failure/return and terminal attempt. Only monotonic_ns, owned PID/start, fixed error category/type, allowlisted errno/known flag, returncode/signal and numeric result fields. No strings from exception messages, argv, environment, terminal, XML/config/vendor state, arbitrary names/paths or their hashes.

Immediately before fork until actual ACK OR existing owned reap: events are bounded memory ONLY, no added filesystem write/fsync/wait. Child immediately closes inherited witness and directory FDs, excludes them from its keep-set; parent alone persists. Existing report pipe is non-inheritable/CLOEXEC and stays open through chdir/execve. At most two fixed14-byte failure frames plus existing ACK; frame contains fixed kind, allowlisted errno and actual child monotonic_ns. Kinds cover parent mismatch, timeout, invalid gate, setup, chdir, exec and other. Failed/partial report write cannot alter the original child exit. After the existing reap, drain only bounded nonblocking bytes before report close, with no waiting; fragments/invalid/absent reports remain UNKNOWN. Keep the2s gate and all existing timeouts unchanged.

ACK permits one bounded persistence and optional single nonwaiting owned-PID/executable-FD identity comparison. Only an actually observed matching executable inode under the retained PID/start can positively establish exec; no poll/delay to catch short-lived execution. EOF/ACK/40/41 alone never establish exec, and a real vendor exit40/41 cannot be classified as pre-exec failure without its explicit frame. A postrelease diagnostic failure cannot claim release was prevented: preserve real release state and run normal owned cleanup.

## Failure, retention and interpretation

Reader rejects wrong binding/sequence/schema/checksum, zero/partial/extra slots and unrecognized fields; it may expose only the previously validated safe prefix. Content validity, terminal-framed stream completeness and durability are separate. TERMINAL records a finalization attempt before flush; readable bytes never prove fsync returned. Missing/truncated/stale/full/failed flush means UNKNOWN where unwitnessed. Checksums detect torn data, not malicious same-UID forgery; records are diagnostic self-reports, never new admission or cryptographic authority.

Diagnostic failures are separate from the original error. Nested cleanup always attempts owned reap, both FD closes and backend cleanup. Best-effort report/event failure cannot replace the original exception/category or original child exit; on otherwise successful execution a diagnostic failure denies a success receipt. Cleanup signal request/result and reaped code/signal stay distinct from unsolicited vendor exit. No events are emitted on every persistent wait iteration.

## Tests, review and future execution blocker

Tests independently distinguish all stage/child branches, ACK/EOF/exit collision, missing/partial/stale/mismatched records, checksum-valid private extras, caps/preallocation/ENOSPC/short-write/final flush and close failure, source/control/invocation/parent drift, no postfork filesystem writes, actual gate-write failure and cleanup signal provenance, original claim/consume/FD safety and unaffected modes. POSIX-only synthetic fork controls run only on supported test hosts; Windows skips are not native qualification.

Existing schema4 require_unspent always checks nonce.recovery. Its already-consumed ATTEMPTED marker remains immutable: even a new control/catalog cannot authorize another start. A future at-most-one diagnostic execution is presently BLOCKED on a separate Root-selected, independently reviewed/published recovery-generation/per-control spent-marker extension or a stop disposition. This slice does not implement that protocol, reset nonce/claim/image/marker, renew old TTL or create a new grant. Any later authorized run must retain same unit/host/image/claim/history, verify actual catalog/control/resource gates, reserve witness, stop on first failure and preserve all evidence. Software completion is not backend/login/market/trading/SDK acceptance.
