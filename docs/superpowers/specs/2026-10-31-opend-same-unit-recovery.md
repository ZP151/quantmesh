# One same-unit persistent OpenD recovery

Issue [261](https://github.com/ZP151/quantmesh/issues/261), blocking the already approved IVV loop in259. Scope selection is Root's implementation decision under the actual existing operator repair/start/login authorization (receipt23cca13f), not a fabricated new human answer.

One user action: recover the exact original inactive persistent console without resetting its initial claim. Success metric: at most one vendor release from a fresh independently consumed recovery control; every failed predicate leaves vendor and saved-credential reads at zero. This is software only; no real control, marker, startup, SDK request, capture intent or trial is generated by this slice.

Reuse the fixed existing unit, nonce, StateDirectory, vendor build, source pins, private terminal, pidfds, gated child and persistent until-operator-stop lifecycle. No unit-template/resource/backend/vendor/SDK/SPA/math/credential-transport changes. Root's later actual startup/storage/source/encryption/capture gates remain independent.

## Routing and authority

Persistent commands with an explicit nonce inspect only the fixed root control `/etc/quantmesh/opend/persistent-recovery.json`. If absent, use the existing initial loader unchanged. If present, load its closed recovery schema and require that exact nonce; malformed/foreign recovery control fails closed, never falls back to an initial permit. Nonpersistent schema1 never uses this control. Existing fixed check-window, prepare, create-pane and pane commands all use this same selector. Runtime reload stays in its originally selected branch.

The separate control schema3 has the existing authority fields plus unit, vendor_sha256, session_lifetime, original_claim and prior_permit. Purpose is opend_same_unit_recovery; exact original persistent unit is derived from nonce; single Operator, same machine/tmux/vendor/launcher hashes and UID/GID; max_seconds180, positive recovery window <=300 seconds, session until_operator_stop. Prior permit is the public root control at the existing fixed persistent-permit path (it may be expired or for another nonce); bind its actual identity and SHA without pretending it was the original instance's authority. The original instance's spent claim must already exist.

Object identities are strict integer device/inode/UID/GID/mode/link-count/size/mtime_ns/ctime_ns maps. New recovery control is root-owned regular mode0444/nlink1 under the existing protected root directory walk. Prior public permit remains root-owned/nlink1/nonwritable to group/other. Original zero-byte claim remains regular, service-owned mode0600/nlink1; its entire expected identity is pinned. No arbitrary paths are accepted.

Root control snapshots, old public permit and original claim are reopened/held and compared by FD and live path identity through release. Replacements, hardlinks, mode/owner drift, exact bytes/hash drift, expiry or wrong source/machine/vendor identity refuse before vendor release. These checks do not read vendor state or credentials.

## Consumption and failure semantics

Check-window, prepare and create-pane can repeat authority checks and verify no recovery consumption exists; they create no recovery consumption. At the final existing gated-child release callback, after current source/manager/terminal/child-cgroup/clock checks, create STATE/<originalnonce>.recovery exactly once with O_EXCL/NOFOLLOW, private0600, full write and file+directory fsync. Bind it to this exact control digest and same original nonce; preserve the old zero-byte initial claim. Hold and recheck all authority objects before/after this atomic step and through the existing gate write.

Exactly one concurrent contender can consume; losers never release. A failure after consumption remains spent, even when the vendor never starts. An earlier failed check consumes nothing and can be corrected only through an explicitly authorized valid control, without changing initial history. No automatic retry/refund or new instance is introduced. Cleanup reuses existing exact owned-child/FD logic; failure must never close a foreign actor or leak a gated child. Successful persistent residency remains until operator stop.

The release method has an optional recovery-only before_gate hook after its existing admission/PID/clock checks. Consumption occurs there, followed by another clock check. Initial callers omit the hook. Original-claim opens are nonblocking and no-follow so a substituted FIFO cannot wait before the regular-file check.
