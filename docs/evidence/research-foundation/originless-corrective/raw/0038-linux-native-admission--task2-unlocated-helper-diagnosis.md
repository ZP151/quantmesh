# Bounded diagnosis: originless numerical-import helpers

The current origin rule will reject legitimate numerical imports. The two root receipts record CPython 3.12.3 importing job_runner plus worker_build in the existing read-only 81-package environment: 888 loaded entries, with five originless helpers. This is import-shape evidence, not image admission or native qualification. No additional interpreter, tests, source edits, build, environment, container, or network dependency operation was performed for this diagnosis; only local receipt/source reads and official upstream source/documentation research.

## Smallest safe proposal

Keep the ordinary file/spec/package-path inventory checks and RECORD-prefix checks. Add one bounded originless-object adapter with three distinct proofs; do not skip entries merely because their names match.

1. typing.io / typing.re: bind the object to the already origin-checked, measured typing module. Require sys.modules entry identity with typing.__dict__['io'/'re'], exact metaclass identity with typing.__dict__['_DeprecatedType'], and exact public-member identities with typing.IO/TextIO/BinaryIO or typing.Pattern/Match. Require the pinned alias class shape (no extra executable attributes, subclass, package path, file/spec override, or altered __all__). Validate the defining metaclass method's code origin against the measured typing source and its globals identity with that module. Inspect raw dictionaries/type attributes without invoking the deprecation metaclass or arbitrary descriptor hooks. This is a defining-code/identity rule, not a pseudo-module name exemption. CPython 3.12.3 explicitly constructs these classes and installs them in sys.modules. [Pinned CPython source](https://raw.githubusercontent.com/python/cpython/v3.12.3/Lib/typing.py)

2. cython_runtime: accept only exact plain ModuleType with the recorded five metadata keys: __name__ equal to the helper name; __doc__/__loader__/__package__/__spec__ None; no __file__, __path__, __getattr__, arbitrary member, subclass, callable, descriptor, capsule or object payload. A forward-compatible choice may permit only cline_in_traceback with exact type bool, as Cython uses that setting; otherwise the observed metadata-only state is the smallest rule and a later setting must explicitly trigger rejection. Such an object contains no helper executable payload. Cython creates it using the module-add API and can populate the boolean setting during traceback handling. [Cython module creation](https://raw.githubusercontent.com/cython/cython/3.2.9/Cython/Compiler/ModuleNode.py), [Cython traceback setting](https://raw.githubusercontent.com/cython/cython/3.2.9/Cython/Utility/Exceptions.c)

3. _cython_3_2_9 / _cython_3_1_4: do not use the data-only rule. The observed dictionaries contain native metatype/function/generator types, plus fused_cython_function for 3.1.4. Names, flags, __module__, basicsize and presence of measured consuming extensions are constraints, not provider evidence. Require a bounded native callback-provider adapter before admitting these caches; if that adapter is outside this checkpoint, leave them rejected and report admission as blocked.

The native adapter can be confined to the recorded native-type caches on pinned Linux x86_64 CPython 3.12:

- Require exact plain-module container and exact permitted metadata/type-key shape. Validate helper values as real type objects, their metaclass/base relationships and raw dictionaries; reject Python-function/property/capsule/unknown additions rather than executing them. Bound traversal by visited identities and fixed limits.
- Use Stable-ABI PyType_GetSlot for the defined executable slots and table slots. Inspect all non-null executable slots, including metatype and relevant bases, not one representative tp_dealloc/tp_call. Inspect bounded, null-terminated tp_methods (every ml_meth) and tp_getset (every non-null getter/setter), including the observed metatype __module__ getset. Table pointers are data, so do not mistake a table's own provider for its callbacks' providers. Require readable bounded mappings before dereferencing; unsupported tables/shape fail closed. [CPython type API](https://docs.python.org/3.12/c-api/type.html), [Documented callback/table structures](https://docs.python.org/3.12/c-api/typeobj.html)
- Cover vectorcall routes as well. PyVectorcall_Function is a public API for retrieving an object's vectorcall pointer on the pinned interpreter; its documentation does not label this particular accessor Stable ABI. Do not claim the entire adapter is ABI-independent merely because PyType_GetSlot is stable. No guessed PyTypeObject offsets. If a reachable callback cannot be enumerated through supported APIs/documented structures, reject that shape or use a separately measured native provider implementation. [CPython call protocol](https://docs.python.org/3.12/c-api/call.html)
- Resolve each direct callable pointer with dladdr to an actual loaded object; require its canonical regular-file origin in the hashed inventory, including admitted libpython/interpreter for inherited slots. Match the currently mapped object's device/inode to the measured provider, rejecting deleted/replaced, anonymous/JIT, unresolved or unmeasured providers. Symbol-name absence alone is not failure when object resolution succeeds. Record at least one helper-owned callback provided by an admitted extension, so inherited libpython trampolines cannot disguise an arbitrary Python imitation. This binds direct helper code providers; it does not certify transitive ELF dependencies or numerical execution. [Linux dladdr](https://man7.org/linux/man-pages/man3/dladdr.3.html)

## Why cheaper checks are insufficient

Cython's cache initializer reuses an existing shared type after type/basicsize checks. For 3.1.4 the defining module association is the originless ABI cache itself; 3.2.9 can also use that association depending on module-state configuration. Therefore PyType_GetModule alone can return another unlocated object. A preloaded foreign native type may be reused by a measured extension; later equality with the consumer's type reference does not prove the provider. The actual receipt found no ordinary extension-dictionary identity references for these cache types anyway. [Cython 3.1.4 cache](https://raw.githubusercontent.com/cython/cython/3.1.4/Cython/Utility/CommonStructures.c), [Cython 3.2.9 cache](https://raw.githubusercontent.com/cython/cython/3.2.9/Cython/Utility/CommonStructures.c)

Moving the fingerprint before importing numerical code alone is incomplete: it verifies an earlier process state, while run_next_job and child runtime-fingerprint boundaries must still bind the actual loaded execution closure. A trusted-bootstrap alternative would need an isolated measured entry, verified import routes/loaders before any numerical import, no unknown preloaded helpers, closure capture after import, and current identity/origin revalidation at each fingerprint boundary. Removing the later scan or relying on the parent's saved tuple would weaken the P2 fix. That is a separate structural change, not the minimum patch recommended here.

## Required tests and counterexamples before admitting helpers

- Positive real-import diagnostic on the existing pinned CPython/numerical closure, followed by the actual manifest gate when an admitted image exists; no claim based only on synthetic sys.modules fixtures.
- Alias: genuine measured aliases pass; replace either alias, substitute a metaclass, attach an external function, change a member or load typing from an external shadow: sanitized refusal.
- Runtime data: exact recorded ModuleType shape (and optional exact bool) passes; ModuleType subclass, __getattr__, callable, capsule, descriptor, unknown key or bool-like user object refuses.
- Native: every observed type including both metatypes/generators/fused type has enumerated admitted providers. Foreign provider substituted only in a method, getset getter/setter, metaclass slot, inherited base callback or vectorcall must refuse even if a sampled deallocator is admitted. Preloading a same-name/same-size foreign type before measured consumers must refuse. Fake Python types with libpython dispatcher slots must refuse; a valid native table containing an unmeasured callback must refuse.
- Provider failure: unresolved, deleted/replaced, symlink/anonymous provider and bounded-table/traversal exhaustion refuse. Mixed admitted extensions/libpython providers pass when directly bound; do not demand every callback belong to one extension.
- Preserve all original external Python/extension/spec/package/namespace shadow rejections, measured base-stdlib acceptance, measured file-entry acceptance, and intentional unmeasured inline-entry refusal. Parent and child still fingerprint actual loaded state rather than an earlier-only tuple.

No new implementation or native pointer probe is supplied here. The receipts establish shapes, not callback-provider coverage. The proposal assumes the existing process integrity boundary; pathname/dictionary inspection cannot certify arbitrary hostile in-process mutation. Provider-slot resolution is a necessary narrowly scoped next proof, not runtime/native certification.
