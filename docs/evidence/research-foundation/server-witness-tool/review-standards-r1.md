1. **P1 — Preserve owned-child cleanup when proc-token observation fails.** `tools/verify_server_market_source.py:380` and `:417`. Trigger: the initial or cleanup `_child_ticks` read raises (for example, unavailable procfs proof). The initial read happens after spawning but before `try/finally`; the cleanup read also raises before killing/joining/closing. Thus the runner can return an error with its newly owned SDK process still running. Offline injection reproduced `new_child_count=1, alive_after_runner_return=true` with a 0.5-second timeout; the probe explicitly stopped only its own child afterwards. A hung non-daemon child can also hold interpreter shutdown indefinitely. This violates ADR-0004 decision 20 and the narrow plan's hard owned-process deadline. Put all post-start operations under cleanup and obtain stable owned-process authority (for example a native handle/pidfd) so absent proc proof cannot strand the child or permit signaling an unrelated PID. Add initial-read and cleanup-read failure regressions.

Validate all rows on the canonical minute grid; match completed rows to both brackets and any transition/partial rows to admitted supplier observations. Add an intermediate-bar refusal test.
