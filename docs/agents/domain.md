# Domain Documentation

QuantMesh uses a single-context documentation layout.

Before exploring or changing code, read:

- `CONTEXT.md` for product language, boundaries and invariants.
- `docs/adr/` for accepted architectural decisions relevant to the change.
- `docs/roadmap/ROADMAP.md` for sequence and exit criteria.
- The active record in `docs/iterations/` for current scope and evidence.

Use glossary terms from `CONTEXT.md` in issue titles, code, tests and documentation. If a proposed change contradicts an ADR, call out the conflict and either follow the ADR or create a superseding ADR.
