# QuantMesh v0.1.1-rc1 — integrated research-to-paper workspace

Package metadata is `0.1.1rc1`; the candidate tag is `v0.1.1-rc1`. This
candidate turns the accepted v0.1.0 workstation into a venue-aware instrument
decision workspace while preserving paper-only execution authority.

## What changed

- One canonical instrument workspace now joins historical and live market
  evidence, comparisons, bounded indicators, multi-horizon forecast intervals,
  proposal lineage, paper positions, P&L, risk and audit evidence.
- Historical/live joins are venue-aware, chronological and provenance-bearing.
  Missing or stale evidence degrades explicitly and never becomes fabricated
  live data or a precise valuation.
- Forecasts use reproducible 7/30/126-session artifacts with out-of-sample,
  calibration, leakage and manifest-pin gates. FinRL-X and NautilusTrader were
  evaluated behind isolated adapters; neither became a runtime dependency.
- Paper proposals require preview plus explicit confirmation, preserve quote
  and forecast fences, journal before publication, and recover without duplicate
  fills. Real-money execution, signing and autonomous AI authority remain absent.
- The React workstation uses the admitted Lightweight Charts adapter, global
  English/简体中文 and theme preferences, responsive layouts and keyboard/screen-
  reader evidence. npm audit, locked-license review and bundle freshness are
  release gates.
- Frontend installation is platform-neutral: native tool bindings remain
  optional, Node `22.12.0` is pinned for CI/development, and frozen installs,
  lint and production builds are verified on both Windows and Linux.

## Safety and known limits

This RC is local-first and paper-only. Live connectors are read-only and may
truthfully report degraded/unavailable when public feeds or local software are
absent. No broker credentials, wallet keys, paid infrastructure, real orders or
AI order authority are enabled. Promotion to `v0.1.1` requires an explicit
operator acceptance verdict after walking the isolated candidate.

Demo reset publishes a newly validated tree atomically and never recursively
deletes a runtime path. For safety on Windows, the previous tree is retained as
a hidden sibling quarantine and its path is reported to the operator. Repeated
resets therefore consume disk until the operator inspects and removes retained
directories outside the running workstation. Automated cleanup is deliberately
not included because a replaceable path cannot provide deletion identity.
