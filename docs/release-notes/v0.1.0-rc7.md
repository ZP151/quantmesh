# QuantMesh v0.1.0-rc7 — release notes

Package metadata `0.1.0rc7` (PEP 440) in both sources and pinned by the
tests; tag `v0.1.0-rc7` on the verified merge commit. v0.1.0-rc6 remains
immutable and is not promoted: the iteration 0019 live research surface
(PR #101) merged into main after rc6 was tagged, so the packaged SPA
changed and the next candidate is cut from the merged tree. This RC
packages the iteration 0019 live research improvements on top of the rc6
baseline (global localization, global preferences, workstation continuity).

## What changed since rc6

Iteration 0019 — Live Research Surface (PR #101, merged at `298825b`),
6 slices delivered across all 4 scope items:

### 1. Unified live board with filter model

- Single watchlist table over the live feed: venue, instrument, source
  label, bid, ask, mid, spread bps, last trade, event/receive time,
  sequence, age and a price-trend sparkline on every row.
- **Filter model**: a search bar with Search icon and clear button
  filters by symbol or venue text, client-side, case-insensitive, with
  an honest empty-state row when nothing matches.

### 2. Research-grade metrics

- Hyperliquid funding rate, mark price, index price, open interest,
  mark–index divergence, short-window return, realized volatility,
  candle volume, trade size, bid/ask depth on the instrument detail
  screen — all derived from the venue-provided `metrics` and `candle`
  frames, never estimated or synthetic in the UI.
- Every metric carries the evidence boundary (event time, receive time,
  sequence, age, provenance) from the normalized `MarketUpdate` contract.

### 3. Charts and density

- **Compact SVG book-depth chart**: per-side L2 depth rendered as
  stacked SVG rects with bid/ask colours, scaling to the mid-price
  range — no charting library dependency (ships with the existing
  SVG boundary).
- **Trade tape**: per-side trade rendering with buy/sell colouring,
  sequence-aware, from the live stream.
- **Price-trend sparkline**: 80×24 SVG polyline per watchlist row
  showing trailing candle closes — green line, scaled to the row's
  price range, hidden when fewer than 2 points are available. Data
  from `GET /api/live/price-trail?symbols=...` through the DuckDB
  replay lake (`LiveBuffer.price_trail`, per-instrument `QUALIFY
  ROW_NUMBER()`).

### 4. Replay and operator drills

- **Recorded replay workflow**: `Recorded replay` card on the cockpit
  renders the lake extent (count, earliest/latest received_at, venues);
  offers 5 min / 15 min / all window actions; shows replayed rows under
  an unmistakable violet `Replay mode` banner with window bounds, update
  count and `source: lake`, plus a clear action. Replay is strictly
  read-only — never folded into the live cache or the paper surface.
- **Operator drills**: coverage audit confirmed healthy and dead-station
  (live smoke), delayed/provenance (supervisor ladder), dropped frames
  (backpressure gate + sequence-gap drills), reconnect
  (`TestDisconnectDrill` + replay fold), and new endpoint-level drills
  for the replay window and price-trail APIs.
- **Browser acceptance**: replay-card honesty (no-lake fail-closed) E2E,
  768 px tablet no-overflow walk added to existing desktop and 390 px
  checks — 7/7 live browser E2E.

### 5. Global locale completion (PR #100, `5069d1b`)

- Completed remaining screen-level translations for Prediction, Kill
  switch, Enablement, NotFound, Loading and shell accessibility/
  provenance copy using the shared en/zh-CN message dictionary.
- API-facing values and server safety verdicts remain semantically raw.

## Safety (unchanged)

All venues read-only; no credentials; no mainnet, real-money trading or
autonomous execution; AI summarize/challenge only; demo and live data
labeled and isolated; paper orders gated by the quote fence. Preferences
are browser-local and are never sent to a venue or broker. The `--demo`
session is the labeled deterministic runtime; `--live` stays labeled real.
Replay data is strictly read-only and never folded into the live cache
or paper surface. Acceptance of this RC does not promote `v0.1.0` —
promotion still requires the separate recorded operator verdict.
