# QuantMesh v0.1.0-rc2 — release notes

The research-to-paper-trade workstation with a real browser product
frontend. RC2 replaces the RC1 server-rendered interface with a
React + TypeScript SPA (ADR-0013) that FastAPI serves from the same
package, and keeps every RC1 guarantee: local-first, fixture-verified,
loopback-only, nothing touches a live venue, and live operation stays
a separate human-gated process.

## What is new in RC2

- **SPA product frontend**: React 19 + Vite 8 + Tailwind 4 + shadcn/ui
  (owned and themed in-tree), compiled into the Python package — no
  node runtime at serve time. Dark-technical black/green treatment,
  responsive shell (desktop sidebar, compact drawer), ⌘K command
  palette, one-click demo reset.
- **Deterministic, labeled demo runtime**: `--demo` seeds a fixed
  scenario (anchor `2026-08-08T12:00Z`, seed `20260809`) into an
  isolated root; every screen carries provenance
  ("Deterministic paper session — seed …"), and reset restores the
  pristine root on demand.
- **Complete browser loop**: market evidence → strategies/predictions
  → simulated order → fill → positions/P&L → risk/audit, all in the
  browser, verified end to end by Playwright.
- **Connectors panel**: per-venue diagnostics (wired/unprobed,
  credentials required, latency), read-only probes, and a
  credential-free public data path — Hyperliquid public REST snapshots
  when the vendored SDK is present, deterministic fixture fallback
  otherwise, with every fallback row explicitly labeled *synthetic*
  and the degraded reason surfaced (missing-software | network |
  rate-limited).
- **Data imports**: CSV / JSON / Parquet → preview with inferred
  column types → column mapping with required-field enforcement →
  commit with per-row rejection reasons (row = file row + 2) →
  provenance-labeled dataset in the lake, all from the browser.
- **Quality gates**: 18 frontend unit/component tests (vitest), 5
  Playwright E2E tests, an Impeccable detector pass with a bounded
  desktop/compact visual review, keyboard-complete focus visibility,
  WCAG 2.2 AA contrast on every screen, and `prefers-reduced-motion`
  support. The clean-checkout release gate now also verifies the
  frontend: `npm ci`, committed-bundle freshness check, and the vitest
  suite.

## Install

Requires Python 3.13 and git.

```text
git clone <this repository>
cd QuantMesh
python -m venv .venv
.venv\Scripts\activate        # Windows; on POSIX: source .venv/bin/activate
python -m pip install -e ".[dev,research,e2e]"
```

## Run — demo mode (recommended for acceptance)

```text
quantmesh-workstation --demo
```

then open <http://127.0.0.1:8765/app/>. The workstation binds loopback
only and runs the deterministic seeded paper session. Every surface
shows its provenance; the reset button in the header restores the
pristine demo root.

## Run — operator mode

```text
quantmesh-workstation
```

opens the same SPA over the operator state root (paper account starts
empty). Demo and imported data are labeled and isolated from
non-demo operator state; reset only touches the demo root.

## Stop and reset

- Stop: `Ctrl+C` in the workstation terminal.
- Demo root: reset from the header button, or delete the configured
  `--demo-root` directory.
- All generated state: delete the data root `~/.quantmesh/`
  (configurable via `QUANTMESH_*` environment variables, see
  `src/quantmesh/settings.py`).

## Safety controls (all fail-closed, unchanged from RC1)

- Live trading is off by default (`allow_live_trading: false`) and no
  code path performs real-money trading, wallet signing, live broker
  orders, credential use, paid infrastructure or AI order authority
  without explicit human approval and a recorded enablement
  transition carrying the exact gate text.
- Workstation binds loopback only; the model gateway defaults to a
  loopback endpoint and refuses remote URLs unless explicitly
  constructed with `allow_remote=True`.
- Global and per-venue kill switches are enforced in the accounting
  risk gate and verified by an E2E drill.
- The connector probes are read-only; the public data path never
  sends credentials (no credentials exist for it).

## Known limitations

- The internal paper venue is the only execution surface; Moomoo and
  Hyperliquid adapters remain read-only market-data surfaces in this
  RC.
- The credential-free public path serves last snapshots for the demo
  symbols (Hyperliquid); when the vendored SDK is absent, it degrades
  to labeled synthetic fixture rows rather than failing.
- Imported datasets are isolated per data root and wiped by a demo
  reset (the reset restores the pristine seeded root).
- The E2E tests run when a shared Playwright browser cache is present
  and are reported as skipped otherwise.
- Frontend CI jobs (build/stale-bundle check in GitHub Actions) are
  deferred to P4; the clean-checkout release gate covers them today.
- The release gate needs ~20 minutes and a working network for a
  fresh install.
