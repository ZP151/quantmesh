> 的 `v0.1.0-rc2` 标签指向 710a931，但源码与隔离安装的包元数据
> 实际仍是 `0.1.0rc1`（pyproject.toml、`__init__.py`、
> tests/test_release.py 三处均为 rc1，测试自身固定 rc1 导致当时的
> 发布门禁无法发现漂移；隔离虚拟环境导入结果为 `0.1.0rc1`）。

> 由 **v0.1.0-rc3**（修复三处版本位置 + 新增「Git 标签必须匹配包
> 版本」门禁步骤）取代。本文档其余安装/启动/验收流程对 rc3 同样
> 适用。

本指南面向操作员（operator）：安装、启动演示、浏览器验收流程、
停止/重置、安全控制、已知限制，以及一份可直接执行的验收清单。
全部命令在本仓库根目录执行；发布提交与验证计数见「发布验证」
一节。

## 1. 安装

要求：Python 3.13 与 git。

```text
git clone <本仓库>
cd QuantMesh
python -m venv .venv
.venv\Scripts\activate        # Windows；POSIX 用 source .venv/bin/activate
python -m pip install -e ".[dev,research,e2e]"
```

安装的就是发布闭包（64 个锁定依赖，含研发/端到端扩展）；前端
由 `tools/build_frontend.py` 在构建期编译进 Python 包
（`src/quantmesh/api/static/app/`），运行期不需要 node。

## 2. 启动（演示模式，推荐验收方式）

```text
quantmesh-workstation --demo
```

然后打开 <http://127.0.0.1:8765/app/>。工作站只绑定回环地址，
并以**确定性种子演示会话**启动：锚点 `2026-08-08T12:00Z`、种子
`20260809`，每次启动同一套数据。每个页面都带来源标识
（「Deterministic paper session — seed …」）；页头「Reset demo」
按钮两次点击后恢复初始种子根目录。

## 3. 浏览器验收流程（市场证据 → 模拟下单 → 持仓/P&L → 风险/审计）

1. 打开「Markets / Watchlist」查看跨市场标的与行情，确认每行有
   来源与时间戳。
2. 「Paper order」选 `hyperliquid` + `SOL-USD`，数量 10，提交；
   结果卡片显示 `filled`。
3. 「Positions / Orders / P&L」确认该订单进入持仓与盈亏，侧栏
   P&L 同步更新。
4. 「Risk / Audit」确认风险告警与审计台账记录了该笔订单。
5. 「Connectors」→「Probe all」：查看每个 venue 的连线状态；
   点击 `BTC-USD` 芯片再「Fetch N snapshots」：有 Hyperliquid
   SDK 时显示真实快照，缺失/失败时显示**标注为 synthetic 的降级
   行**并给出原因（missing-software | network | rate-limited）。
6. 「Data imports」：上传一个 CSV（`timestamp,open,high,low,close
   ` 列），确认预览/列类型推断/映射自动填充，填数据集名与标的并
   「Commit dataset」；结果卡显示 accepted/rejected 及逐行原因
   （文件行号 = 行号 + 2）。
7. 任意页面用键盘 Tab 走查：每个可聚焦控件都有可见焦点环。
8. 页面缩窄到 ~390px（或浏览器移动模式）：无横向页面滚动，侧栏
   收起为抽屉，密集表格在卡片内横向滚动。
9. 系统开启「减弱动态效果」（prefers-reduced-motion）后：所有
   过渡/动画折叠为单帧。

## 4. 停止 / 重置

- 停止：在工作站终端按 `Ctrl+C`。
- 重置演示数据：页头「Reset demo」两次点击；或删除启动时指定的
  `--demo-root` 目录。
- 重置全部生成状态：删除数据根目录 `~/.quantmesh/`（可用
  `QUANTMESH_*` 环境变量改路径，见 `src/quantmesh/settings.py`）。
- 演示数据与操作员状态隔离：演示重置只清演示根目录；导入数据集
  归属当前数据根并带 `operator-import` 来源标识。

## 5. 安全控制（全部默认拒绝，与 RC1 一致）

- 实盘交易默认关闭（`allow_live_trading: false`）。任何真实资金
  交易、主网钱包签名、真实经纪商订单、凭据使用、付费基础设施、
  AI 下单权限，都必须先获得明确的人工批准，并在启用台账中记录
  携带逐字门禁文本的启用迁移。
- 工作站仅绑定回环；模型网关默认回环端点。
- 全局与分市场急停开关在会计风险门中强制生效，并由 E2E 演练
  验证。
- Connectors 探针只读；免密公共数据路径不携带任何凭据（也不存在
  凭据）。

## 6. 已知限制

- 本 RC 唯一执行面是内部纸面 venue；Moomoo 与 Hyperliquid 适配器
  仅为只读行情面。
- 免密公共路径只覆盖演示标的的近期快照（Hyperliquid）；SDK 缺失
  时降级为标注 synthetic 的 fixture 行，而不是失败。
- 演示重置会清掉导入数据集（重置=恢复初始种子根目录）。
- 共享 Playwright 浏览器缓存存在时 E2E 用例运行，否则报告为
  skipped。
- 前端 CI（GitHub Actions 中的构建/过期包检查）推迟到 P4；当前
  由干净检出发布门禁覆盖。
- 发布门禁约需 20 分钟，且全新安装需要可用网络。
