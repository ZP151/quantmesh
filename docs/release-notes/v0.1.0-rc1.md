# QuantMesh v0.1.0-rc1 — release notes

A local-first, fixture-verified research and paper-trading workstation.
This release candidate is the first operator-facing product line
(`0.1.x`, iteration 0013): every behavior is verified from a fresh
checkout, nothing in it touches a live venue, and enabling live
operation is a separate, human-gated process.

## What is inside

- **Data**: normalized fixture/public market data with a local lake,
  Moomoo and Hyperliquid adapters, prediction-market intelligence
  (Polymarket, Kalshi) with cross-platform event mapping.
- **Research**: reproducible experiments, walk-forward strategy
  reports, signal promotion with drift/failure alerts, and forecast
  reports with calibration.
- **Execution**: internal paper trading with a fee model, an order
  journal, and journal-replay recovery (the M10 recovery drill).
- **AI research layer**: local/OpenAI-compatible model gateway
  (loopback by default), structured analyst roles, retrieval over
  filings/news/experiments/audit logs, citable decision records.
- **Workstation**: a loopback-only web UI — 13 screens covering
  overview, watchlists, instruments, positions, orders, P&L,
  experiments, promotions, forecasts, risk, audit, kill switch and
  enablement.
- **Operational hardening**: idempotency keys, kill-switch
  enforcement, a signed audit export, an enablement approval ledger,
  and the release gate itself.

## Verified against

- Package metadata `0.1.0rc1` (PEP 440) in both sources, pinned by
  tests.
- Deterministic license gate over the pinned release closure
  (`.[dev,research,e2e]`, 64 packages); ambient environments fail
  loudly instead of drifting.
- Audit lock consistency: every declared dependency pinned in
  `requirements-audit.txt` at a version satisfying its specifier.
- One-command clean-checkout release gate
  (`python tools/release_gate.py`): fresh clone -> fresh venv ->
  Ruff -> license review -> pip-audit (isolated) -> full test suite
  -> golden path -> clean-checkout proof.
- Release-closure install, full test suite and the 53-check golden
  path from a clean checkout — exact counts and the tested commit are
  recorded in the gate summary below.

## Install

Requires Python 3.13 and git.

```text
git clone <this repository>
cd QuantMesh
python -m venv .venv
.venv\Scripts\activate        # Windows; on POSIX: source .venv/bin/activate
python -m pip install -e ".[dev,research,e2e]"
```

## Run

```text
quantmesh-workstation
```

then open <http://127.0.0.1:8765>. The workstation binds loopback
only (a non-loopback host is refused at construction) and boots with
a fresh paper account — it never places a real order.

## Demo the golden workflow

```text
python tools/golden_path.py
```

Fixture data -> data lake -> strategy reports -> internal paper ->
all 13 screens (first boot and after a restart, ports 8643/8644),
then every audit ledger re-read. Prints PASS/FAIL per check, uses a
temporary state root, and leaves the checkout clean.

## Stop and reset

- Stop: `Ctrl+C` in the workstation terminal.
- Reset all generated state: delete the data root
  `~/.quantmesh/` (configurable via `QUANTMESH_*` environment
  variables, see `src/quantmesh/settings.py`).
- Nothing in the repository writes outside the data root and the
  venv; the golden path writes only to its own temporary root.

## Safety controls (all fail-closed)

- Live trading is off by default (`allow_live_trading: false`) and
  no M10 code path can perform real-money trading, wallet signing,
  live broker orders, credential use, paid infrastructure or AI
  order authority without explicit human approval and a recorded
  enablement transition carrying the exact gate text.
- Workstation binds loopback only; the model gateway defaults to a
  loopback endpoint and refuses remote URLs unless explicitly
  constructed with `allow_remote=True`.
- Global and per-venue kill switches are enforced in the accounting
  risk gate and verified by an E2E drill.
- The enablement ledger records every request/approve/withdraw/revoke
  transition with actor and timestamp.

## Known limitations

- The internal paper venue is the only execution surface; Moomoo and
  Hyperliquid adapters are read-only market-data surfaces in this RC.
- Moomoo OpenD simulated-account and Hyperliquid testnet drills are
  optional operator-dependent validation, not part of the RC.
- The E2E tests run when a shared Playwright browser cache is
  present and are reported as skipped otherwise; the golden path does
  not depend on the browser.
- On non-Linux platforms the six Linux-only closure members (uvloop,
  jeepney, SecretStorage, cryptography, cffi, pycparser) are pinned
  and tolerated as absent.
- The release gate needs ~15 minutes and a working network for a
  fresh install.
