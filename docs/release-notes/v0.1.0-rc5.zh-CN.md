# QuantMesh v0.1.0-rc5 — 发布说明

包元数据 `0.1.0rc5`（PEP 440）在两个来源中一致并由测试固定；标签
`v0.1.0-rc5` 位于已验证的合并提交上。v0.1.0-rc4 不提升：操作员授权的
2026-08-10 验收审查发现迭代 0015 驾驶舱存在四个发布候选缺口，而修复后的
候选树比不可变的 rc4 标签更新，因此 rc4 保持为历史记录（issue #94）。本 RC
打包该验收加固，并取代 Phase G 的自我验收记录。

## 自 rc4 以来的变更

Phase G 后验收加固（issue #94，经 PR #95 于 `c47b83d` 合并）：

- **标的详情从最新快照水合** — `/app/cockpit/:symbol` 原先只监听未来的
  流帧，断开的源在 `/api/live/state` 已有最新报价/成交/盘口时仍显示空页。
  详情页现在先水合该快照，并在流更新前每 10 秒周期性地与快照对账。
- **壳层与概览按运行时诚实展示** — 壳层原先总是查询 `/api/demo/status`，
  概览在 live 模式下也声称全部数据是合成的。`/api/health` 现在上报
  `runtime_mode`（demo/live/operator）；demo 查询在非 demo 模式下禁用；
  壳层/页脚文案随模式变化；live 概览明确区分纸面台账与驾驶舱。
- **live 冒烟契约失败即关闭** — `tools/live_smoke.py` 原先接受错误状态的
  health 与不完整的 state/status 结构。现在对 health 状态、带时区的
  时间戳、payload 对象、venue/instrument 身份、kind 映射诚实性、非
  unavailable 的空 kinds 与空的 venue 表面均失败即关闭。
- **replay 的包含式追加边界** — 仅按时间戳的 replay 无法区分同一
  `received_at` 的两次追加；`LiveBuffer.replay(through_local_seq=...)`
  是 `append` 返回的包含式边界，每个中间状态都可复现。
- **workstation E2E 引导竞态修复** — 旧套件先探测固定端口 8642，再在
  uvicorn 绑定前释放探测；fixture 现在把已绑定的 OS 保留 loopback 套接字
  交给 uvicorn（16/16，无探测-绑定窗口）。DuckDB 时区回归断言被加强
  （连接在 `America/New_York` 打开、构造函数固定 UTC），预期的 fixture
  取消不再泄漏为 pytest 线程警告。
- 重建的打包 SPA bundle 随修复一起提交。

## 验证

- Ruff 干净；定向后端验收 82/82；前端 Vitest 48/48；workstation 浏览器
  E2E 16/16；live E2E 5/5；bundle 新鲜度与 TypeScript/Vite 生产构建
  最新。
- 源码树 live 工作站（8768）：health `runtime_mode=live`；更严格的冒烟
  演练 14/14 通过（BTC/ETH 真实、AAPL/NVDA 诚实不可用）；桌面浏览器审查
  中驾驶舱与 BTC 详情从过期快照水合、零控制台错误；390×844 无横向溢出
  （`scrollWidth == clientWidth == 390`）。
- 合并树（`c47b83d`）上的全新检出发布门禁：**15/15 通过** — 15 步全部
  在全新确定性环境中通过，包括完整 pytest 套件（761.4 秒，含
  Playwright 浏览器 E2E）与 golden path 演练（53/53）；克隆检出保持
  干净。首次尝试在 pytest 中途被宿主机终止，零测试失败（此前 12/12
  步通过）；通过的那次运行使用仓库 venv 解释器启动，因为版本一致性
  步骤先于门禁自建的全新 venv 运行且需要 `packaging`。打标签后对精确
  标签树的门禁运行记录在迭代检查点与验收记录中。
- 其余与 rc4 相同：React 19 + Vite + Tailwind 4 + shadcn/ui SPA
  （ADR-0013）、带溯源与两次点击重置的确定性 `--demo` 运行时、带新鲜度
  标签的 live 只读多 venue 驾驶舱、确定性报价栅栏、免凭据公共连接器路径
  与带标签的合成回退、CSV/JSON/Parquet 导入与逐行拒绝原因、键盘/WCAG
  2.2 AA 覆盖，以及全新检出发布门禁（15 步，golden path 53/53）。

## 安全（不变）

所有 venue 只读；无凭据；无 mainnet、真实资金交易或自主执行；AI 仅
总结/质询；demo 与 live 数据带标签且隔离；纸面订单由报价栅栏把关。
`--demo` 会话是带标签的确定性运行时；`--live` 保持标签为真实。验收本 RC
不提升 `v0.1.0` — 提升仍需单独记录的操作员裁决。
