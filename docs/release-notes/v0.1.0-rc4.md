# QuantMesh v0.1.0-rc4 — release notes

Package metadata `0.1.0rc4` (PEP 440) in both sources and pinned by the
tests; tag `v0.1.0-rc4` on the verified merge commit. v0.1.0-rc3 was
rejected by the operator (2026-08-09) after a browser re-review found
two product defects: the Forecasts screen exposed neither a probability
nor a calibration explanation, and the SPA sidebar hardcoded `rc2`
while API/package metadata reported rc3. The operator fixed both
defects locally and verified the fix by browser acceptance, kill-switch
409 drill, keyboard walk and full-suite runs; this RC packages that
fix. The published `v0.1.0-rc3` tag is the historical record and is
not rewritten.

## What changed since rc3

- **Forecasts expose acceptance evidence** (`8f462de`): each forecast
  market card now shows the latest observed probability, its observed
  timestamp and the liquidity confidence, an explicit calibration
  explanation (Brier scoring on the number of resolved test windows,
  or a stated reason when no resolved observations exist — never a
  fabricated score), and a labeled source line ("venue implied
  probability · deterministic seeded observation"). The backend
  `MarketForecast` model now retains the latest observation explicitly
  (`latest_probability`, `latest_probability_at`, timezone-aware and
  validated, `latest_liquidity_confidence`) instead of making the API
  reconstruct a current quote from historical windows.
- **SPA sidebar version comes from the API** (`8f462de`): the
  hardcoded `rc2` badge in the desktop sidebar and mobile drawer is
  replaced by `v{version}` read from `GET /api/health` — the same
  source the footer already used — with an honest `local` fallback
  when health is unavailable.
- The rebuilt frontend bundle is committed with the fix, so the
  packaged app (one process, no Node.js at runtime) serves the fixed
  chrome and Research screen.
- Everything else is unchanged from rc3: the React 19 + Vite + Tailwind
  4 + shadcn/ui SPA (ADR-0013), the deterministic labeled `--demo`
  runtime with provenance and two-click reset, the complete
  research-to-paper-trade browser loop, the credential-free public
  connector path with labeled synthetic fallback, CSV/JSON/Parquet
  import with per-row rejection reasons, keyboard/WCAG 2.2 AA coverage
  and the release-gate step that pins tag == package version == newest
  release notes (PEP 440 compare).

## Install

Requires Python 3.13 and git.

```text
git clone <this repository>
cd QuantMesh
python -m venv .venv
.venv\Scripts\activate        # Windows; on POSIX: source .venv/bin/activate
python -m pip install -e ".[dev,research,e2e]"
```

## Run — demo mode (recommended for acceptance)

```text
quantmesh-workstation --demo
```

then open <http://127.0.0.1:8765/app/>. The workstation binds loopback
only and runs the deterministic seeded paper session. Every surface
shows its provenance; the reset button in the header restores the
pristine demo root.

## Run — operator mode

```text
quantmesh-workstation
```

opens the same SPA over the operator state root (paper account starts
empty). Demo and imported data are labeled and isolated from
non-demo operator state; reset only touches the demo root.

## Stop and reset

- Stop: `Ctrl+C` in the workstation terminal.
- Demo root: reset from the header button, or delete the configured
  `--demo-root` directory.
- All generated state: delete the data root `~/.quantmesh/`
  (configurable via `QUANTMESH_*` environment variables, see
  `src/quantmesh/settings.py`).

## Safety controls (all fail-closed, unchanged from rc1)

- Live trading is off by default (`allow_live_trading: false`) and no
  code path performs real-money trading, wallet signing, live broker
  orders, credential use, paid infrastructure or AI order authority
  without explicit human approval and a recorded enablement
  transition carrying the exact gate text.
- Workstation binds loopback only; the model gateway defaults to a
  loopback endpoint and refuses remote URLs unless explicitly
  constructed with `allow_remote=True`.
- Global and per-venue kill switches are enforced in the accounting
  risk gate and verified by an E2E drill.
- The connector probes are read-only; the public data path never
  sends credentials (no credentials exist for it).

## Known limitations

- The internal paper venue is the only execution surface; Moomoo and
  Hyperliquid adapters remain read-only market-data surfaces in this
  RC.
- The credential-free public path serves last snapshots for the demo
  symbols (Hyperliquid); when the vendored SDK is absent, it degrades
  to labeled synthetic fixture rows rather than failing.
- Forecast probability evidence is the deterministic seeded
  observation, explicitly labeled as such in the UI — live streaming
  probabilities are the next iteration (Live Market Cockpit).
- Imported datasets are isolated per data root and wiped by a demo
  reset (the reset restores the pristine seeded root).
- The E2E tests run when a shared Playwright browser cache is present
  and are reported as skipped otherwise.
